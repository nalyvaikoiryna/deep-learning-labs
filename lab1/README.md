# 2. Стандартизація даних

Середнє значення та стандартне відхилення обчислювалися лише на навчальній вибірці.

Для кожної ознаки:

$$
\mu_j =
\frac{1}{N}
\sum_{i=1}^{N} x_{ij}
$$

Стандартне відхилення:

$$
\sigma_j =
\sqrt{
\frac{1}{N}
\sum_{i=1}^{N}
(x_{ij}-\mu_j)^2
}
$$

Для обчислення стандартного відхилення використовувалось:

```python
ddof=0
```

Стандартизація виконувалася за формулою:

$$
x'_{ij} =
\frac{x_{ij}-\mu_j}{\sigma_j}
$$

У коді:

```python
mean = X_train.mean(axis=0)
std = X_train.std(axis=0, ddof=0)

X_train = (X_train - mean) / std
X_test = (X_test - mean) / std
```

Для `X_test` використовуються ті самі `mean` та `std`, які були обчислені на `X_train`.

# 3. Архітектура нейронної мережі

Використовується мережа:

```text
X -> Linear(4, 8) -> ReLU -> Linear(8, 3)
```

Розмірності параметрів:

| Параметр | Розмірність |
|---|---:|
| `W1` | `(4, 8)` |
| `b1` | `(8,)` |
| `W2` | `(8, 3)` |
| `b2` | `(3,)` |

Для ініціалізації параметрів створюється новий генератор:

```python
rng = np.random.default_rng(0)
```

## W1

Для першого шару використовується He initialization:

$$
W_1 \sim
\mathcal{N}
\left(
0,
\sqrt{\frac{2}{4}}
\right)
$$

```python
W_1 = rng.normal(
    loc=0.0,
    scale=np.sqrt(2 / 4),
    size=(4, 8)
)
```

Bias:

```python
b_1 = np.zeros((8,), dtype=np.float64)
```

## W2

Для другого шару використовується Xavier initialization:

$$
W_2 \sim
\mathcal{N}
\left(
0,
\sqrt{\frac{2}{8+3}}
\right)
$$

```python
W_2 = rng.normal(
    loc=0.0,
    scale=np.sqrt(2 / (8 + 3)),
    size=(8, 3)
)
```

Bias:

```python
b_2 = np.zeros((3,), dtype=np.float64)
```

# 4. Прямий прохід

Навчальна вибірка має розмірність:

```text
X_train: (105, 4)
```

## Перший Linear шар

$$
Z_1 = XW_1+b_1
$$

Розмірності:

$$
(105,4)(4,8)+(8)
\rightarrow
(105,8)
$$

Тому:

```text
Z1: (105, 8)
```

## ReLU

$$
A_1 = ReLU(Z_1)
$$

де

$$
ReLU(x)=\max(0,x)
$$

У NumPy:

```python
A_1 = np.maximum(0, Z_1)
```

Розмірність:

```text
A1: (105, 8)
```

## Другий Linear шар

$$
Z_2=A_1W_2+b_2
$$

Розмірності:

$$
(105,8)(8,3)+(3)
\rightarrow
(105,3)
$$

Тому:

```text
Z2: (105, 3)
```

`Z2` містить логіти трьох класів.

# 5. Стабільний log-softmax та cross-entropy

Для запобігання чисельному переповненню з кожного рядка логітів віднімається його максимальне значення:

$$
s_i =
z_i-\max_j(z_j)
$$

У коді:

```python
shifted = Z_2 - np.max(
    Z_2,
    axis=1,
    keepdims=True
)
```

Після цього:

$$
\log p_i =
s_i -
\log
\left(
\sum_j e^{s_j}
\right)
$$

У коді:

```python
exp_shifted = np.exp(shifted)

sum_exp = np.sum(
    exp_shifted,
    axis=1,
    keepdims=True
)

log_probs = shifted - np.log(sum_exp)
```

Для кожного об'єкта вибирається log-probability правильного класу:

```python
correct_log_probs = log_probs[
    np.arange(len(y_train)),
    y_train
]
```

Cross-entropy, усереднена за всіма об'єктами:

$$
L =
-\frac{1}{N}
\sum_{n=1}^{N}
\log p_{n,y_n}
$$

У коді:

```python
loss_numpy = -np.mean(correct_log_probs)
```

Отримане значення:

```text
NumPy loss = 1.4562007801142816
```

# 7. Зворотне поширення похибки

## 7.1. Градієнт за логітами

Для комбінації softmax та cross-entropy:

$$
\frac{\partial L}{\partial Z_2}
=
\frac{P-Y}{N}
$$

де:

- $P$ — softmax;
- $Y$ — one-hot представлення правильних класів;
- $N=105$.

Softmax:

$$
p_i =
\frac{e^{s_i}}
{\sum_j e^{s_j}}
$$

У коді:

```python
softmax = exp_shifted / sum_exp
```

One-hot матриця явно не створюється.

Замість цього:

```python
dZ2 = softmax.copy()
dZ2[np.arange(N), y_train] -= 1
dZ2 /= N
```

Розмірність:

```text
dZ2: (105, 3)
```

---

# 8. Градієнти другого шару

Другий шар:

$$
Z_2=A_1W_2+b_2
$$

Градієнт за вагами:

$$
dW_2=A_1^TdZ_2
$$

Розмірності:

$$
(8,105)(105,3)
=
(8,3)
$$

Тому:

```text
dW2: (8, 3)
```

Градієнт за bias:

$$
db_2 =
\sum_{n=1}^{N}
dZ_{2,n}
$$

У коді:

```python
db2 = np.sum(dZ2, axis=0)
```

Розмірність:

```text
db2: (3,)
```

Градієнт за входом другого Linear шару:

$$
dA_1=dZ_2W_2^T
$$

У коді:

```python
dA1 = dZ2 @ W_2.T
```

Розмірність:

```text
dA1: (105, 8)
```

---

# 9. Градієнт через ReLU

Похідна ReLU:

$$
ReLU'(z)=
\begin{cases}
1,&z>0\\
0,&z\le0
\end{cases}
$$

Тому:

$$
dZ_1 =
dA_1
\odot
\mathbb{1}(Z_1>0)
$$

У коді:

```python
dZ1 = dA1 * (Z_1 > 0)
```

Розмірність:

```text
dZ1: (105, 8)
```

---

# 10. Градієнти першого шару

Перший шар:

$$
Z_1=XW_1+b_1
$$

Градієнт за вагами:

$$
dW_1=X^TdZ_1
$$

Розмірності:

$$
(4,105)(105,8)
=
(4,8)
$$

Тому:

```text
dW1: (4, 8)
```

Градієнт за bias:

$$
db_1=
\sum_{n=1}^{N}
dZ_{1,n}
$$

У коді:

```python
db1 = np.sum(dZ1, axis=0)
```

Розмірність:

```text
db1: (8,)
```

Підсумкові розмірності:

| Градієнт | Розмірність |
|---|---:|
| `dW1` | `(4, 8)` |
| `db1` | `(8,)` |
| `dW2` | `(8, 3)` |
| `db2` | `(3,)` |

Кожен градієнт має ту саму розмірність, що й параметр, за яким він обчислюється.

# 11. Перевірка за допомогою PyTorch

Було створено еквівалентну мережу:

```python
model = nn.Sequential(
    nn.Linear(4, 8),
    nn.ReLU(),
    nn.Linear(8, 3)
).double()
```

У PyTorch використовувався `float64`.

У модель були скопійовані ті самі параметри, що використовувалися у NumPy.

`torch.nn.Linear` зберігає ваги у форматі:

```text
(out_features, in_features)
```

Тому при копіюванні ваг використовується транспонування:

```text
NumPy W1:   (4, 8)
PyTorch W1: (8, 4)

NumPy W2:   (8, 3)
PyTorch W2: (3, 8)
```

Для loss:

```python
loss_torch = nn.functional.cross_entropy(
    logits,
    y_torch
)
```

Для отримання градієнтів:

```python
loss_torch.backward()
```

# 13. Чисельна перевірка градієнтів

Для чисельного диференціювання використовувалась центральна різниця:

$$
g_{num,i}
=
\frac{
L(\theta_i+\varepsilon)
-
L(\theta_i-\varepsilon)
}
{2\varepsilon}
$$

де

$$
\varepsilon=10^{-6}
$$

Перевірялись параметри:

```text
W1[0, 0]
b1[0]
W2[0, 0]
b2[0]
```

Для кожного параметра:

1. зберігалося початкове значення;
2. параметр змінювався на `+eps`;
3. обчислювався $L_+$;
4. параметр змінювався на `-eps`;
5. обчислювався $L_-$;
6. початкове значення відновлювалося;
7. обчислювався чисельний градієнт.

Критерій:

$$
|g_{num}-g_{manual}|
\le
10^{-7}
$$

Результати:

| Параметр | Градієнт `backward()` | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---:|---:|---:|---|
| `W1[0,0]` | `-0.01992018433055532` | `-0.019920184390898044` | `6.034272387323014e-11` | Так |
| `b1[0]` | `-0.07056611158437998` | `-0.0705661116207068` | `3.632683043264251e-11` | Так |
| `W2[0,0]` | `0.13523020860547605` | `0.13523020869765645` | `9.218040220027035e-11` | Так |
| `b2[0]` | `0.08552164484195579` | `0.08552164498798476` | `1.4602897e-10` | Так |

Усі чотири різниці менші за $10^{-7}$.

Отже чисельна перевірка підтвердила правильність ручного backward.

# 14. Дослід із навмисною помилкою

Для перевірки здатності тестів знаходити помилки у backward було навмисно прибрано ділення на кількість об'єктів у градієнті за логітами.

Правильна реалізація:

```python
dZ2 = softmax.copy()
dZ2[np.arange(N), y_train] -= 1
dZ2 /= N
```

Помилкова реалізація:

```python
dZ2 = softmax.copy()
dZ2[np.arange(N), y_train] -= 1
```

Функція втрат, PyTorch-реалізація та формула чисельного диференціювання не змінювались.

# 15. Прогноз перед запуском помилкової реалізації

Loss не повинен змінитися, оскільки помилка знаходиться лише у backward.

Правильний градієнт за логітами:

$$
dZ_2 =
\frac{P-Y}{N}
$$

У помилковій реалізації:

$$
dZ_2^{bug}=P-Y
$$

Отже:

$$
dZ_2^{bug}=N\cdot dZ_2
$$

Для цієї навчальної вибірки:

$$
N=105
$$

Тому очікується:

$$
dW_1^{bug}=105dW_1
$$

$$
db_1^{bug}=105db_1
$$

$$
dW_2^{bug}=105dW_2
$$

$$
db_2^{bug}=105db_2
$$

Очікувані результати перевірок:

- loss NumPy / PyTorch — перевірка пройде;
- градієнти NumPy / PyTorch — перевірка не пройде;
- numerical / manual gradients — перевірка не пройде.

# 19. Висновки

У лабораторній роботі було вручну реалізовано прямий та зворотний прохід двошарової нейронної мережі у NumPy.

Ручні градієнти були перевірені двома незалежними способами:

1. за допомогою PyTorch autograd;
2. за допомогою чисельного диференціювання.

Для правильної реалізації різниці між NumPy та PyTorch знаходяться приблизно на рівні $10^{-17}$ — $10^{-16}$, що значно менше допустимого порога $10^{-12}$.

Різниці між ручними та чисельними градієнтами знаходяться приблизно на рівні $10^{-11}$ — $10^{-10}$, що також значно менше допустимого порога $10^{-7}$.

Таким чином обидва способи перевірки підтвердили правильність ручного backward.

Під час експерименту з навмисною помилкою функція втрат не змінилася, оскільки forward залишився правильним.

Водночас після вилучення ділення на $N=105$ усі ненульові ручні градієнти збільшилися у 105 разів.

Як PyTorch-перевірка, так і чисельне диференціювання успішно виявили цю помилку.

Таким чином правильне значення loss саме по собі не гарантує правильності реалізації backward, тому градієнти необхідно перевіряти окремо.

Для запуску backward без ділення на `N`:

```bash
uv run python lab1.py --buggy
```

У цьому режимі:

```python
dZ2 /= N
```

не виконується.

Очікується:

```text
Loss passed: True

```

Чотири чисельні перевірки також повинні повернути:

```text
False
```

За замовчуванням використовується правильна реалізація.
